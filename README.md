# 实训学时合规与冻结服务

该服务汇聚学员签到、导师确认和请假修正事件，按培养方案与时区重放学时状态，并保存可追溯的学期冻结快照。项目还提供导师分配、证明材料、豁免复核、规则版本、名额、通知和数据留存等领域模块，供后续业务扩展时复用统一的状态与审计约束。

## 学期结算关账窗口

学期结束后仍会有导师补确认和请假修正，因此正式冻结前提供一个可控、可追溯的关账窗口，而不是瞬间冻结。每个窗口严格依次经过五个阶段，每一步都有固定责任角色与期限：

1. **数据截止** `data_cutoff`（data_clerk）—— 确定事件边界，记录计划所在时区的本地截止时刻
2. **异常清单** `exception_list`（compliance_officer）—— 列待确认签到、负向修正与未达标学员
3. **补录宽限** `grace_entry`（mentor_coordinator）—— 宽限期内允许补录，结束时扩展截止边界
4. **复核签署** `review_signoff`（dean_reviewer）—— 电子签署
5. **正式冻结** `frozen`（registrar）—— 生成不可覆盖快照，窗口完成

接口前缀 `/api/plans/{plan_version}/settlement-windows`：

| 动作 | 接口 |
| --- | --- |
| 启动 | `POST /`（可指定各阶段责任人 `owners` 与带时区期限 `deadlines`） |
| 状态查询 | `GET /`（列表）、`GET /{window_id}`（阶段、材料、审计、版本、任务） |
| 推进 | `POST /{window_id}/advance`（由当前阶段责任角色调用） |
| 暂停 / 恢复 | `POST /{window_id}/pause`、`/resume`（仅 registrar/admin） |
| 重开 | `POST /{window_id}/reopen`（仅已冻结；批准角色必须不同于签署人与冻结教务员，批准人也不能是本人） |

关键约束：

- 窗口行带 `row_version` 乐观锁，并发推进/暂停/重开只有一方生效，其余收到 409。
- 重开生成新版本（revision +1），新版本重新走五阶段；每版冻结出独立 `freeze_id`（`{window_id}-r{n}`），旧快照与已封存材料永不覆盖，可用既有 `/freezes/.../diff/...` 对比版本。
- 每个阶段的超时动作持久化在 `settlement_tasks` 表；后台调度线程按期限强制推进，租约过期的任务在进程重启后由启动恢复继续，执行失败按指数退避补偿重试，超过上限进入死信。

## 运行方式

默认数据保存在项目目录的 SQLite 文件中。安装依赖后执行 `uvicorn app.main:app --host 127.0.0.1 --port 8000`，健康检查地址为 `/health`，业务接口位于 `/api`。

## 测试

```bash
python3 -m pytest -q
```

```bash
python3 -m compileall -q app tests
```

测试覆盖事件幂等导入、跨时区与跨日学时合并、实习确认、负向修正、冻结快照和差异查询；结算窗口另外覆盖并发推进（乐观锁）、暂停/重开权限、跨时区截止、后台超时、重启恢复与失败补偿。运行过程中不需要单独的数据库或网络服务。
